da6idb.batch

Gridding a run of scans onto one common lattice.

expand_scans(start, end, step=1)

The scan numbers from start to end inclusive, every step.

Given 152, 160, 2 this is [152, 154, 156, 158, 160]. The ends may be the other way round, and a step of zero is taken to mean one.

parse_scans(text)

Scan numbers from what someone typed: "152, 154 157-160".

find_scans(folder)

{scan number: image path} for the pva files in folder.

grid_scans(folder, numbers, hkl_range=None, oversample=1.0, output=None, step=None, reuse=True, normalize_transmission=True, on_start=None, on_geometry=None, on_done=None, progress=None)

Grid several scans onto one lattice. Returns [(number, path, note)].

path is None for a scan that could not be done, and note says why. The cell size comes from the first scan that reads successfully unless step is given outright. With normalize_transmission each scan's frames are divided by its attenuator transmission where that varies, which is decided per scan -- a series can mix scans that moved their filter with scans that did not.

da6idb.files

Finding the files a scan is made of, and pairing them up.

detector_files_from_metadata(master)

The detector file paths the master records, in the order it lists them.

The value reads lambda250k: /some/where/scan_00001.h5, one detector per line; older masters write an empty {} there, which yields nothing.

image_path_for_master(master)

The image file belonging to master, or None if none is next to it.

Tried in turn: the detector file the master names -- where it points, then relative to the experiment root, then by name beside the master -- the file_name in the older pva_streaming block, and last the <master stem minus "_master"> -> pva_<stem>.h5 convention. Newer masters name a file that follows no convention at all (test_00001.h5 beside test_00001_master.hdf), which only the recorded name can find.

master_path_for_image(image)

The master file this image file belongs to.

Beside the image first. Failing that, a short walk up the tree, trying each ancestor and each ancestor's copy of the image's own directory name -- which is where the master sits when the detector writes into a parallel tree. The name is specific enough (<scan>_master.hdf) that the search stays safe; callers that already know the pair should pass it rather than rely on this.

read_master_rois(master)

The detector's ROIs as recorded in the master's baseline.

Newer image files carry no entry/data/rois of their own, so this is the only record of where the detector's ROIs were. The numbers are the same ones the older writer put in the image file -- a corner and a size in pixels -- so they come back in the same shape.

is_image_file(path)

Whether path is itself an image file (i.e. it holds an image stack).

resolve_image_file(path)

The image file to open for path, which may be a master or an image file.

Selecting a pva*.h5 directly in the file list is the obvious way to ask for it, so that opens itself rather than hunting for a partner.

scan_number(path)

The scan number in a file name: 00008 from tise2_2_00008_master.hdf.

The last run of digits wins, so the prefix's own digits (tise2_2) are ignored and the sibling pva_tise2_2_00008.h5 reports the same number.

file_prefix(path)

The part of a file name in front of the scan number: tise2_2.

Everything from the scan number onwards is dropped, so the files of one series all reduce to the same string.

list_hdf_files(directory)

Return the HDF5 files directly inside directory, sorted by name.

da6idb.hkl.convert

Turning detector frames into a cloud of points in reciprocal space.

build_converter(geometry)

The xrayutilities area-detector converter for this geometry.

frame_hkl(geometry, hxrd, frame)

(H, K, L) for every pixel of one frame, each shaped like the detector.

classHklCloud

The reduced point cloud handed to the plotter.

.bounds(self)

((h0, h1), (k0, k1), (l0, l1)) of the points kept.

convert(geometry, first=0, last=None, step=1, threshold=0.0, max_points=2000000, progress=None)

Map the selected frames into (H, K, L), keeping the interesting pixels.

Every pixel of every frame is a point, which for a long scan is far more than can be held or drawn -- 601 frames of 516x516 is 160 million. So each frame is reduced as it is converted: pixels at or below threshold are dropped, and if what survives still exceeds max_points the brightest are kept. Reducing per frame keeps the full set from ever being in memory.

da6idb.hkl.detector

The scattering angle a detector pixel sees, from xrayutilities' geometry.

circle_delta(geometry)

What the delta circle read on each frame.

The angle of the centre pixel, which is what the motor is set to -- not the angle of whatever the detector was actually looking at.

detector_basis(hxrd, detector_angles)

Pixel (0, 0) and one step along each pixel axis, in lab coordinates.

getDetectorPos returns the direction to each pixel with the arm rotations applied. That position is affine in the pixel indices, so these three vectors give any pixel, whole or fractional, exactly.

two_theta_maps(geometry, x, y, hxrd=None)

Scattering angles at pixel coordinates x, y, for every frame.

Returns (maps, index): one array shaped like x per distinct detector position, and which of them each frame uses. Frames that leave the detector where it was share a map, so a scan that never moves it evaluates once however many frames it has and however large the region.

two_theta_at(geometry, x, y, hxrd=None)

The scattering angle at pixel (x, y) on each frame, in degrees.

x and y are detector pixels indexed as the frame is stored, and may be fractional -- a centre of mass usually is. Give one position, or one per frame.

The detector basis is rebuilt only when the circles move, so a scan that leaves the detector still costs one call however many frames it has.

read_transmission(image, master, n_frames, frame_epoch=None)

Attenuator transmission for each frame, or None if nothing records it.

The image file stores one reading per frame, which is what a frame was actually taken through; the master samples at scan points and misses the transients the free-running detector catches, so it is only a fallback.

read_geometry(image, master=None, angles_from_master=False, use_setup=True)

The conversion parameters for image, master first where it has them.

The angles are the exception. The image file records a POSITION with each frame, while the master records one per scan point, on a read-back clock that lags the exposure -- matching those onto the frames shifted every frame of a rocking curve by one whole step, which would move the entire map. So the per-frame values win when they exist; angles_from_master forces the resampled ones, and the window exposes the choice.

da6idb.hkl.grid

Bin a pva detector stack onto a regular HKL grid and save it as .vti.

classGridCancelled

Raised when a progress callback asked to stop, so nothing is written.

A short digest of everything that decides where a pixel lands.

Stored in the .vti so a cached grid is not reused after the UB, the energy, the detector geometry or the angles have been edited -- the HKL range alone would not notice.

sampling_cell(geometry, frame=None, stride=8)

What the sampling supports, in HKL units.

Returns (volume_per_sample, frame_gap, in_plane): the Jacobian volume each sample speaks for, the perpendicular separation between consecutive frames, and the spacing between neighbouring pixels within a frame.

sampling_footprint(geometry, frame=None, stride=8)

How far one sample reaches along each axis -- the fuzzy spread width.

The axis-aligned extent of the sampling parallelepiped. This is emphatically not the cell size: the parallelepiped is skewed, so its bounding box is several times its volume.

natural_step(geometry, oversample=1.0, frame=None)

The cell size the sampling supports: a cube holding about one sample.

oversample scales it -- above 1 for fewer, better-filled cells, below 1 for a finer grid. Because samples are spread over their footprint, a finer cell stays continuous instead of breaking into layers.

measured_range(geometry, sample_frames=8)

The HKL box the scan actually reaches, as (low, high) triples.

Useful for choosing a range to give a whole batch before gridding any of it.

default_output(image, hkl_range=None, oversample=1.0)

Where the grid for this file, range and detail level is kept.

matches_range(path, hkl_range, tolerance=1e-06)

Whether an existing .vti was made for this HKL range.

grid_to_vti(image, master=None, hkl_range=None, output=None, step=None, width=None, oversample=1.0, first=0, last=None, frame_step=1, max_cells=MAX_CELLS, reuse=True, progress=None, geometry=None, normalize_transmission=None)

Bin image onto a regular HKL grid and write it as a .vti.

hkl_range is (h_min, h_max, k_min, k_max, l_min, l_max); without it the whole measured extent is used. step overrides the automatic cell size and width the fuzzy footprint. Returns the path written -- or the existing one, when reuse is set and a grid for the same range is on disk.

ensure_grid(image, master=None, hkl_range=None, output=None, reuse=True, geometry=None, oversample=1.0, **kwargs)

Return (grid, path, regridded) for this file and HKL range.

A cached .vti is reused when the HKL range, the frame range and the geometry it was made for all match what is being asked for now; otherwise the data is gridded and written. Unlike calling grid_to_vti then load_vti, the cached file is read once.

make_drawable(grid, fill=0.0)

Replace NaN in a loaded grid so a volume mapper can draw it.

NaN marks cells the scan never reached. Handed to a GPU volume mapper it does not come out transparent -- it lights the whole empty region up -- so it has to become a value at the bottom of the colour scale, where the opacity ramp starts at zero.

Edits the array in place, which on a large grid saves copying a few hundred megabytes, and returns (low, high) of the measured cells read before the NaN goes. The file on disk still holds the NaN.

to_xarray(grid, name='intensity')

A gridded map as an DataArray with real H/K/L coordinates.

The same numbers as the .vti, but labelled: cube.sel(L=7.52, method="nearest").plot() is then a one-liner, and slicing by coordinate beats remembering which index is which. Unmeasured cells stay NaN, which is what xarray and matplotlib both expect of missing data.

xarray is imported here rather than at the top so the rest of the package stays usable without it.

da6idb.hkl.slice

Cutting a plane through a gridded map.

plane_basis(normal)

Two in-plane directions for normal, preferring the HKL axes.

When the normal is along an axis the other two axes span the plane exactly, and they are returned in H, K, L order so an L slice is drawn H across and K up. Otherwise any orthonormal pair will do.

plane_origin(centre, normal, offset=0.0, point=None)

Where the cutting plane sits, from an offset or from a point on it.

An offset is measured from centre along the unit normal, which is fine for sweeping a plane through a map but awkward when you already know the H, K, L you want to cut through: naming the point places the plane directly, and the plane is then the one through it.

Returns (origin, offset) either way -- the second being how far the plane ended up from centre -- so a viewer can always show both descriptions of the same plane, whichever was typed.

slab_offsets(layers)

Offsets, in cells, of a slab of layers planes centred on zero.

sample_volume(grid, points)

Trilinear values of grid at arbitrary HKL points; NaN off the grid.

average_along_normal(grid, points, normal, layers=1, step=None)

Average grid over a slab of layers cells centred on points.

A plane has no thickness, so a slice of one cell is as noisy as the data gets. Averaging a few cells either side along the normal trades a little resolution across the plane for a great deal less noise in it.

line_cut(grid, start, end, samples=None, width=1, normal=None, step=None)

Intensity along the segment from start to end, both in HKL.

The two points name the cut outright, which is what you want when the line runs between features whose H, K, L you know -- dragging one into place by eye cannot be written down or repeated.

width averages that many parallel lines, spaced step apart and centred on the segment, the way a slab average thickens a plane. Their offset direction is perpendicular to the line and, when normal is given, inside that plane, so widening a cut on a slice stays on the slice instead of wandering out of it.

Returns (distance, points, values): distance from start in HKL units, the (n, 3) H, K, L of each sample, and the intensity there, NaN wherever the scan did not reach.

sample_plane(grid, normal, origin, pixels=None, layers=1)

Resample grid on the plane. Returns (image, us, vs, u, v, origin).

image is indexed [row, column], columns running along u and rows along v; us and vs are the sample positions as distances from origin along each. Points off the grid come back NaN. With layers above one the plane is averaged over that many cells along its normal.

da6idb.images

The detector's image stack, and everything recorded alongside it.

nearest_index(frame_epoch, scan_epoch)

For each frame, the scan point closest to it in time.

Shared with hkl_viewer, which matches the master's diffractometer angles onto the frames the same way.

evenly_spaced_index(n_frames, n_scan_points)

Map each frame onto a scan point by position, not by time.

Used only when the image file has no per-frame timestamp to match against (see read_scan_channels), so frame 0 takes scan point 0, the last frame takes the last scan point, and the rest are spread evenly in between.

read_scan_channels(image, frame_epoch, n_frames=None, master=None)

The master file's primary fields, resampled onto the image's frames.

The detector free-runs, so the two files rarely have the same number of points -- 103 frames against 101 scan points is typical, the camera starting a moment early. Each frame therefore takes the value of the scan point nearest it in time; frames outside the scan hold the first or last point.

When the image file carries no per-frame timestamp at all, there is no clock to match against, so frames are instead spread evenly across the master's scan points by position (see evenly_spaced_index) -- a rougher alignment, but the best available without a time base.

This answers the question you have in front of an unfamiliar scan: which name goes in as x, as y, as the monitor. Mean and spread of psic_h/k/l over the scan, or None if not recorded.

The spread matters as much as the mean: on a rocking curve one of the three sweeps across the peak while the others hold still, and a bare average would read like a fixed position.

grid_stats(grid)

.two_theta_angles(self, roi=0, background=None)

The scattering angle of what roi held, frame by frame.

The detector circle reads the angle of the centre pixel, so a feature anywhere else is at a different two theta. This asks xrayutilities for the angle of every pixel in the region, through the same geometry the HKL conversion uses, and averages them weighted by the counts in each -- both detector circles included, not just delta.

roi is anything rect takes, or None for the whole frame. Returns one angle in degrees per frame.

.two_theta(self, roi=0, background=None, weight='sum')

One two theta for the whole scan: two_theta_angles averaged.

Weighted by weight, an ROI metric, so the frames where the feature was lit count for more than the ones where the box held nothing. The default weighs by the counts actually used -- background-subtracted, when background is given, which is what makes the weighting mean anything on a region whose background is a large part of its sum. Pass weight=None for a plain mean over the frames.

The average is taken over the per-frame angles rather than over one summed image, so it stays right if the detector moved during the scan.

A plane through the grid, as a labelled 2D array.

Cells the scan never reached come back as NaN, as they do from grid, so they are left blank by .plot() and kept out of its colour scaling rather than painted the bottom colour.

The plane is placed either by offset -- how far along the normal from the centre of the map -- or by point, an H, K, L the plane must pass through, which is usually what you actually know. The result records both, and with a point the plane's own coordinates are measured from it.

Cuts the lattice grid last built unless told otherwise, so asking for a coarse grid and then slicing it does not quietly produce a second one at full resolution.
